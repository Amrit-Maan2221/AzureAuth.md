## 🚗 **“Extra Security at the Workshop Gate”**

Your app **Workshop Pro** is now used by many car workshops.
Everything works fine — users log in, permissions work, life is good.

But one day, a workshop security manager says:

> “We want **extra safety**.
> Not everyone should access the app from anywhere or any device.”

So Azure brings a powerful security guard called:

> 🛡 **Conditional Access**

Think of it like:

> “You can enter **only if certain rules are true**.”

---

## 🧱 **What Conditional Access Can Do (Simple Examples)**

A workshop may say:

✔ Allow login only if user does **Multifactor Login (OTP or Authenticator)**
✔ Allow access **only from company laptops** (Intune enrolled devices)
✔ Block access from **unknown locations or risky IP addresses**

Just like a real workshop might say:

> “Mechanics can enter only with badge + security check.”

---

## 🧩 **How Does This Affect Your App?**

Good news:

👉 In most cases, **your app does not need any code changes**.
Conditional Access runs **in Azure**, not inside your app.

Users just see:

* MFA prompt
* device check
* location restriction message

And then continue logging in.

---

## ⚠️ But Sometimes Your App *Must* Handle a “Challenge”

This happens when your app:

* calls **another API**
* or signs in **silently** (without showing login screen)
* or uses **on-behalf-of flow**
* or is a **single-page app**

In these cases, Azure may say:

> “Stop — more security needed. Show login again with extra checks.”

Your app must then:
👉 show an interactive sign-in screen
👉 user completes MFA or security rule
👉 then continue

This is called a **Conditional Access challenge**.

---

## 🏭 **Workshop Story Example**

### 🟢 **Example 1 — Simple Case (No Code Needed)**

You build a **single-tenant iOS app**.

Policy added:

> “User must do MFA when signing in.”

User logs in → MFA screen appears → they approve → app works
You didn’t change any code.

---

### 🟡 **Example 2 — App Calling Another API (Needs Challenge Support)**

Your app works like this:

👤 User →
🌐 Your Web App →
🔧 Middle Service →
📦 Downstream API (for invoices)

A customer adds a security policy to the **downstream API**:

> “Only users with MFA can access this API.”

Flow happens:

1️⃣ User signs in → token sent to middle service
2️⃣ Middle service calls downstream API
3️⃣ API says:

> “Security challenge — MFA required”

4️⃣ Middle service returns challenge to your app
5️⃣ Your app must:
👉 show MFA challenge
👉 user completes it
👉 request token again
👉 retry call

Now app works 👍
